## Review findings and change

1. The intent covers sandbox, merchant, SKU/name, quantity, exact/unit/maximum
   amount, currency and lifetime. Ed25519 signs the versioned digest/action/time.
   The trusted key is supplied by the terminal, never the model response.
2. Transport uses fixed sandbox hosts with redirects rejected; no live mode,
   endpoint override, recurring operation or payment-source input is exposed.
3. A durable reservation precedes network access. Stable, separate create and
   capture request IDs complement the reservation. Errors prohibit blind retry.
4. Approved scope is checked before capture; final fetched order and capture
   response must agree before receipt creation. Receipts omit payer data and
   distinguish fixture evidence. A digest is not provider attestation.
5. **Gap fixed:** CREATED/APPROVED order reconciliation previously ignored an
   existing `payments` field. Six new tests demonstrated acceptance of prior
   captures, authorizations and refunds before the fix. The adapter now rejects
   such responses before capture POST and requires reconciliation. Existing
   order state alone is insufficient for this one-fresh-capture policy.
6. The new offline evidence verifier requires an independently retained digest
   and trusted approval key, revalidates signatures/scope/expiry/capture evidence,
   and checks envelope labels. It explicitly does not independently verify
   provider or model execution. Five verifier tests cover key/digest substitution,
   semantic tampering, fixture labeling and saved-file verification/error output.

No dependency, package export, core protocol, Python source or existing payment
rail was changed. New code and synthetic data remain under the repository MIT
license. Runtime-model licensing remains pending because no model ran.
